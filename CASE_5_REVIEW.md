# Кейс-задача №5

## Аналитический обзор кейс-задачи №4  
**WEB-приложение «Туризм» (FastAPI + PostgreSQL)**

---

## Введение

В рамках кейс-задачи №4 было разработано WEB-приложение на тему «Туризм», реализующее клиент–серверную архитектуру с использованием FastAPI и PostgreSQL.

Настоящий аналитический обзор выполнен по критериям, указанным в кейс-задаче №5, и направлен на оценку качества разработанной системы, выявление возможных недостатков и формирование предложений по её дальнейшему развитию.

---

## Функциональность

Разработанная система реализует следующие функции:

- проверка доступности сервиса (`GET /health`);
- получение списка туров (`GET /tours`);
- создание заявки на тур (`POST /orders`);
- получение списка заявок (`GET /orders`);
- автоматическая документация API через Swagger/OpenAPI.

В базе данных реализованы:

- таблица `tours` (справочник туров);
- таблица `orders` (заявки клиентов);
- внешний ключ `orders.tour_id → tours.tour_id`.

**Оценка:**  
Функциональность соответствует требованиям задания: реализована WEB-архитектура, REST API, реляционная БД и SQL-скрипт.

## Производительность

На текущем этапе система демонстрирует высокую скорость отклика благодаря:

- минимальной бизнес-логике;
- простым SQL-запросам;
- отсутствию ресурсоёмких операций.

### Потенциальные ограничения

- отсутствие пагинации при выборке данных;
- отсутствие индексов для ускорения запросов при росте объёма данных.

### Возможные улучшения

- внедрение пагинации (`limit`, `offset`);
- добавление индексов по `created_at` и `tour_id`;
- кэширование часто запрашиваемых данных.

## Безопасность

Текущая версия является учебным MVP и не включает механизмы аутентификации.

### Потенциальные риски

- отсутствие авторизации;
- открытый доступ к созданию заявок;
- отсутствие ограничений по количеству запросов.

### Рекомендации

- внедрение JWT-аутентификации;
- настройка HTTPS;
- ограничение доступа к списку заказов;
- внедрение rate limiting.

## Выявленные проблемы и способы их решения

| Проблема | Предлагаемое решение |
|-----------|---------------------|
| Нет пагинации | Добавить параметры `limit` и `offset` |
| Нет авторизации | Реализовать JWT |
| Нет статусов заказов | Добавить поле `status` |
| Нет миграций | Использовать Alembic |
| Нет автотестов | Подключить pytest |
| Нет индексов | Добавить индексацию в БД |
